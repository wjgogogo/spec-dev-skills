# Refactoring UI 应用准则

按当前界面的问题选择相关主题。示例数值用于帮助判断，优先复用现有项目的设计 token。

## 1. 从功能开始与有限选项

- 从一个具体功能的输入、内容、操作和结果开始。先确定功能，再选择导航与页面外壳，避免没有内容依据的布局决定。
- 早期可以用草图或灰度稿探索内容分组和注意力顺序；已经成熟的彩色界面不必为了执行流程重新画灰度稿。
- 用可使用的小循环发现长文本、错误出口和数据量问题。不要在可交付版本中展示尚未支持的功能入口。
- 将风格意图落实到字体、颜色、圆角和文案。颜色或圆角对性格的影响是线索，不能推导固定品牌规则；尊重现有语言和样式。
- 优先从已有字号、间距、颜色、阴影选项中选择。现有选项直接造成问题时允许在授权范围内做最小修正；缺少系统时先为重复决定建立小规模刻度，而不是先建设完整组件库。
- 比较相邻的、有明显差别的选项，例如 16 / 24 / 32px 图标。不要为了几乎不可察觉的 1px 差异反复试探。

## 2. 视觉层级

### 注意力与视觉重量

- 按任务区分主要、辅助和较少使用的内容。用字号、字重、前景对比、位置和空间共同表达，不让字号独自承担全部层级。
- 重要内容不突出时，先检查附近的竞争者。减弱次要按钮、图标、侧栏背景或元数据，可能比继续放大主内容更有效。
- UI 正文避免随意使用极细字重来弱化信息；优先调整对比和层级，同时保持可读性。
- 实心图标常比同色文字更重，必要时降低图标对比。浅色细边框不明显时，可以适度加宽，但不要把装饰规则用于弱化必要控件边界。
- 彩色背景上的辅助文字可选相近色相的专用颜色，调整明度与饱和度。透明文字可能显得褪色或透出背景图案；仍需检查实际对比。

### 内容与操作

- 对能通过格式和上下文识别的数据，省略冗余的“标签：值”，或写成“剩余 12 件”等自然单元。此原则不授权删除表单标签或辅助技术所需名称。
- 标签通常支持数值；用户在参数表中寻找字段名称时，标签反而可以更突出。根据扫描目标决定层级。
- HTML 标题等级表达文档结构，CSS 表达视觉层级。不要只为得到某个字号改变标题语义，也不要强制应用页面的 `h1` 使用巨大的视觉样式。
- 在同一个任务区域中，让真正的主要操作明显，次要操作清楚但安静，较少使用的操作保持可发现。多任务区域可以各有主要操作，不能机械限制全页只能有一个实心按钮。
- 危险操作的视觉强调还取决于当前任务。在普通设置页可以使用次要表达，在危险确认步骤中明确风险和确认操作；保留既有数据保护流程，不新增不必要的确认步骤。

操作样式可从以下候选开始比较，结合现有组件和实际对比选择：

| 操作层级 | 优先尝试的视觉表达 |
| --- | --- |
| 主要操作 | 高对比实心背景 |
| 次要操作 | 描边或较低对比背景 |
| 较少使用的操作 | 文字操作 |

这些是表达层级的起点，不要求替换已经清楚有效的样式。视觉上采用文字样式的操作仍应保留正确的按钮或链接语义。

## 3. 布局与间距

- 探索新布局时可从较充足的空间开始，再收紧。监控台、数据表等高密度界面根据任务效率确定密度，不套用展示页留白。
- **组内距离小，组间距离大**。标签靠近自己的输入框，标题靠近对应正文，多行列表项内部比项目之间更紧。先用间距表达分组，再决定是否需要边框。
- 间距和尺寸刻度应在大尺寸端扩大档位差异。仅规定“4 的倍数”仍留下许多难以区分的选择。
- 间距与尺寸刻度示例：`4, 8, 12, 16, 24, 32, 48, 64, 96, 128, 192, 256, 384, 512, 640, 768`。按现有系统取子集或复用其刻度，不要求全量使用。
- 内容有自己的合适宽度。表单、正文、导航、图像可以不同宽；必要时把说明文字拆到另一列，避免为填满宽屏拉长表单。
- 使用网格帮助对齐，但不要让每个元素都按百分比缩放。侧栏可以使用适合内容的宽度，主区域弹性扩展；屏幕不足时再切换布局。
- 对登录卡片等内容设定合适的最大宽度，在空间不足时才收缩。检查断点前后的跳变、溢出与可用性。
- 响应式设计中独立调整标题、正文、间距和布局。较大的标题通常需要收缩更多，正文仍要可读；不要统一等比例缩小。
- 不同大小的按钮可以分别调整内边距和文字尺寸。以点击目标和场景为依据，不把组件当作整体缩放的截图。

## 4. 排版

- 收敛零散字号。字号刻度示例：`12, 14, 16, 18, 20, 24, 30, 36, 48, 60, 72`，一个界面通常只需要其中少数几档。
- 人工选择实用档位可以比固定数学比例更适合应用界面。无需为了黄金比例改写已有字号系统。
- 全局字号 token 可用 `rem` 或 `px`；注意嵌套 `em` 会相对父级计算而偏离刻度。这不代表所有 CSS 尺寸都不能使用相对单位。
- 优先使用项目现有、适合小尺寸阅读的字体。检查真实中文、拉丁文字、数字和字重；字体有多种字重是筛选线索，不是质量证明。
- 英文正文可从每行约 45–75 个字符开始调整。中文需根据字体、字号和列宽实际判断，不能直接套用字符数。外层布局较宽时仍可单独限制正文宽度。
- 行高与行长、字号共同决定：较长的行和较小的字通常需要更多行间空间，大标题可以更紧。检查实际多行内容，不全局套用同一行高。
- 同一行混合字号的文字优先观察基线对齐，例如价格与“/月”；图标和按钮是否居中则按实际组件判断。
- 较长段落按语言阅读方向对齐，居中更适合短内容。数值列通常右对齐；严格的小数点对齐还需要统一精度或专用布局，右对齐本身不保证。
- 英文两端对齐需要留意不均匀的词间空白和断词。中文排版按项目实际规则处理。
- 尊重字体默认字距。英文全大写可适度增大字距，某些大标题可以略收紧；不要机械应用到中文。
- 正文链接应容易识别，链接密集的导航或列表可采用较克制的样式。不能仅依赖悬停让重要入口可发现；触屏、键盘焦点及交互反馈也需清楚。

## 5. 颜色

### 可用色板

- 根据用途组织中性色、主色、状态与分类色。完整产品需要同色的多档深浅，不能只靠几种鲜艳色值。
- 灰阶常承担正文、辅助文字、背景、边框等角色；主色用于主要操作和选中态；状态色服务于成功、警告、错误等语义。
- 没有现成色板时，从适合实际按钮的中间色、适合文字的最深色和适合背景的最浅色开始，填充中间档位，再放入组件中调整。
- `100–900` 等编号仅是组织方法，不能推断任意同档位颜色具有同样对比。不要为每个组件临时生成近似颜色。
- HSL 的色相、饱和度、明度便于解释调整；同样的 HSL 明度不代表同样的视觉亮度。颜色层级需视觉判断，文字可读性需实际对比检查。
- 极浅或极深的颜色可能显得褪色，可以调整饱和度并小幅改变色相；例如让深黄色略向橙色移动。属于调色手段，不是每档都必须执行的公式。
- 灰色可带少量冷或暖色相，保持整个灰阶温度协调。保留用户品牌方向，不统一套用蓝灰。

### 信息表达与可读性

- 非主操作的状态标签，可以用浅色背景配深色文字，降低大块深色背景的视觉竞争。
- 文字弱化不能以牺牲阅读为代价。评估实际文字颜色与实际背景，不能只看设计 token 名称或透明度数值。
- WCAG 2.2 AA 的基础文字对比要求是普通文字至少 4.5:1，大字至少 3:1。大字通常至少 18pt（24 CSS px）普通字重，或 14pt（约 18.67 CSS px）粗体。
- 这些数值只覆盖文字对比的相关要求，不能据此宣布完整无障碍合规。涉及其他控件、图表或合规验收时查看适用标准。
- 重要状态、趋势和错误不能只用颜色表示。结合文字、正负号、图标、线型或其他可辨识提示；方向上升是否有利取决于指标语义。
- 图表中仅调整线条明暗也不保证可辨识，必要时加入直接标注、不同线型或标记。

准确条件见 [W3C：Understanding SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。对最新规范或严格合规的判断使用适用的官方资料，设计经验不能替代标准要求。

## 6. 深度

- 上方光源可帮助理解凸起元素的顶部高光与下方投影、凹陷元素的内阴影。只借用足够的空间线索，不追求写实材质。
- 阴影表达元素的相对层级：普通卡片较轻，菜单和弹出面板更明显，模态层可更强。复用已有 elevation 档位，不能每个元素随意定义阴影。
- 拖动时增加阴影、按压时减弱阴影可以辅助表达交互状态；只有当前任务包含对应交互时才改动。
- 两层阴影可分工：较大柔和投影表达空间距离，较小集中的投影定义边缘。更高的空间位置通常弱化紧贴边缘的阴影。
- 不使用模糊阴影也可以通过背景明暗、短实心投影和元素重叠表达层次。明暗带来的空间感是情境性线索，需结合整体主题验证。
- 卡片跨越背景区块、头像叠放等能形成层次；检查遮挡、裁切和交互区域。叠放图片可用与背景接近的间隔边界减少冲突。

## 7. 图片

- 尽早用有代表性的真实素材，检查构图、光线、色调和比例。高质量占位照片不能证明替换为真实素材后仍然成立。
- 图片上文字的对比取决于其覆盖区域。可以使用遮罩、降低图片对比、统一色调或柔和文字阴影，但需检查不同裁切和实际素材，阴影不保证对比合格。
- SVG 不像位图那样像素化，但图标仍有适合的目标尺寸。小图标放大可能过粗且缺细节；保留较小图标并放进容器，或选适合目标尺寸的素材。
- 小尺寸标志或 favicon 需要保留关键轮廓，复杂大图直接缩小可能失去辨识度。
- 产品截图大幅缩小后，细节可能不可读。选择局部截图、较小布局的截图或更多展示空间；只需介绍结构时可使用简化示意，清楚说明其性质。
- 用户上传图片可用固定展示比例维持布局。裁切适合头像和封面，必须看完整内容的附件应保留全貌。检查主体位置和不同比例。
- 图片与页面背景融合时可用轻微内阴影或半透明边界保留轮廓，避免强硬边框与图片冲突。

## 8. 完成度

- 先改善已有元素：有意义的列表图标、引用表达、符合主色的选中态。自定义控件保留可访问名称、键盘操作和可见焦点；不为装饰重造控件行为。
- 少量强调边框或选中标记可以引入颜色，避免所有卡片和区块同时强调。
- 背景渐变、纹理和几何形状保持足够低的视觉重量，不妨碍文字阅读。普通业务页不必为了完成清单增加背景装饰。
- 首次使用的空状态说明用途并提供下一步。可以收起确实无用的筛选和统计；筛选后无结果时保留筛选与恢复路径，加载失败也不能伪装成无数据。
- 边框、背景差异、阴影和间距都可以表达分隔。删除重复分隔前检查分组是否仍然清楚，不强制全部去边框。
- 组件按信息任务组织。无需独立排序的信息可以在同一表格单元格中建立主次；保留用户需要的排序、筛选和比较能力。
- 下拉菜单可包含分组和说明，重要单选项可采用选择卡片。外观变化不改变底层语义和操作保证。

## 练习与校准

观察优秀界面中自己原本不会做的决定，解释其目的。复现后比较行高、字重、间距、对齐和层级，找出产生差异的具体因素。

## 评审表达示例

“创建、导入、导出均为高对比实心按钮，用户难以辨认当前主要操作。若本页主要任务是创建，将导入改为次要按钮、导出改为较轻的操作；在实际页面检查创建入口是否先被注意到，同时保留导出入口的发现性。”

该示例说明建议需要任务依据、可见现象和验证方式，不规定每个页面都采用同样的按钮样式。
